How Django Works: The MVT Pattern

Django follows the Model-View-Template (MVT) architecture pattern, designed for rapid development with clean separation of concerns.

🗄️

1. Model (Data Layer)

Defines your database structure, relationships, and validations in pure Python code using Django's powerful ORM.

models.py
⚙️

2. View (Logic Layer)

Handles incoming HTTP requests, executes business logic, queries models, and returns an HTTP response or rendered template.

views.py
🎨

3. Template (Presentation)

HTML files enriched with Django Template Language (DTL) tags to dynamically display data passed from views.

templates/
🛣️

URL Dispatcher (Router)

Maps clean URL patterns to their respective view functions or class-based views.

urls.py

Directory Architecture

📁 int/ (Project Root)
├── 📁 .venv/               # Isolated Python virtual environment
├── 📁 config/              # Central project configuration hub
│   ├── settings.py         # App configurations, middleware, databases, environment
│   ├── urls.py             # Root URL routing table
│   ├── wsgi.py             # Web Server Gateway Interface (Production synchronous)
│   └── asgi.py             # Asynchronous Server Gateway Interface (Async / WebSockets)
├── 📁 core/                # Core application module
│   ├── admin.py            # Model registration for admin panel
│   ├── apps.py             # App registry configuration
│   ├── models.py           # Database entities & ORM models
│   ├── views.py            # Business logic handlers
│   └── urls.py             # App-specific URL routes
├── 📁 templates/           # Global and modular HTML templates
│   ├── base.html           # Master layout template (Navbar, messages, footer)
│   └── core/index.html     # This dashboard template
├── 📁 static/              # Raw static assets (CSS, JS, Images)
├── 📁 media/               # User-uploaded files directory
├── .env                    # Secret keys and environment-specific settings (Ignored by Git)
├── .env.example            # Safe environment template for team / deployment
├── .gitignore              # Protects secrets, cache, and virtual environments
├── requirements.txt        # Pinned dependencies for reproducible installs
└── manage.py               # Django command-line administrative utility
